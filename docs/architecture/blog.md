# Blog and content

The RailsPress engine, mounted at `/railspress`, is the authoring back-office: draft, publish and schedule posts with Lexxy rich text, categories, tags, optional authors, automatic slugs, per-post SEO fields, header images and galleries, custom entities, CMS blocks and a JSON API — all behind its admin UI at `/railspress/admin`.

It ships **no public reader pages**; its routes are admin and API only. The reader-facing frontend is the app's own `BlogController` (`app/controllers/blog_controller.rb`), serving `/blog` and `/blog/:id` by slug, unauthenticated. The index lists published posts newest first with optional `category` and `tag` slug parameters as filters, both matched through a join so an unknown slug lists no posts (a category looked up first would be `nil`, and `where(category: nil)` lists every uncategorized post), eager-loading the category, tags and header image to satisfy the strict Bullet gate. It is paginated `BlogController::PER_PAGE` posts at a time (see pagination.md), and the page links keep the active filter; the sitemap is not paginated and still lists every published post. The show action renders the post's Action Text content and sets SEO through the meta-tags gem, falling back to the title and a truncated plain-text body. A draft or an unknown slug is a `404`. The views in `app/views/blog/` are DaisyUI and the copy is i18n'd — the engine owns the back-office, the public presentation is the app's and is meant to be restyled.

The show page caches the rendered content and the plain-text fallback description under the post's cache key, the content also under the locale. Rendering resolves every embedded attachment with its own query and partial, so an uncached post with ten images costs about three times the CPU of a cached one. Action Text touches the post whenever its content changes, which expires both entries.

A change that does not touch the post keeps the old fragment until the post is next saved: a purged embedded blob, or setting `config.active_storage.urls_expire_in`, whose expiring signed URLs would then outlive their expiry inside the cached HTML.

**Admin authorization is the one seam each app is expected to change.** `/railspress/admin` is gated by the shared superadmin basic auth only as a safe default: `config/initializers/railspress.rb` names `RailspressAdminAuth`, and `app/controllers/concerns/railspress_admin_auth.rb` just includes `SuperadminAuthentication`. Conceptually the blog admin belongs to a content editor — an ordinary user with a content role — not to the developer superadmin; it is gated this way only because authorization is capability-only here and open self-registration makes gating on "is signed in" unsafe. Re-gating means editing that single concern to a before_action that authorizes a content editor.

Two integration notes. A narrow Bullet safelist in `config/environments/test.rb` covers the post-to-taggings unused-eager-loading warning, a verified `has_many :through` false positive where the join is loaded to serve the tags and never touched directly. And the engine declares an `excerpt` field but ships no `excerpt` column, so `Railspress::Post#excerpt` does not exist — do not reach for it.

The engine adds its own pins to the app's import map, and every pin is preloaded unless it says otherwise, so each public page would download the RailsPress admin controllers that only the admin layout imports. `config/importmap.rb` pins `railspress` and its controllers again with `preload: false`: the admin still resolves them, and no other page fetches them. A later engine pin that is not repeated there is preloaded on every page again.

The admin layout imports `railspress` from an inline module script with no nonce, which the strict Content Security Policy would block, leaving every engine Stimulus controller unregistered. The policy allows that one snippet by its hash (see security-headers.md). `test/system/railspress_admin_test.rb` opens the admin without the accessibility audit the rest of the system suite runs: the engine's sidebar credit link fails axe's `link-in-text-block` rule in both schemes, and that markup belongs to the engine, not to this app.
