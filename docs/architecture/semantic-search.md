# Semantic search

`Document` (`app/models/document.rb`) carries an Action Text `content` and a `embedding` vector of `Document::EMBEDDING_DIMENSIONS` floats, declared to Neighbor with `has_neighbors`. `Document.semantic_search` embeds the query through RubyLLM and returns the nearest neighbours by cosine distance. `config/initializers/neighbor.rb` calls `Neighbor::SQLite.initialize!`, which loads the sqlite-vec extension; without it the column is just a blob.

Re-embedding is driven by an `after_save_commit` callback guarded by `embedding_source_changed?`, which asks whether the title or the rich-text body changed. Guarding on the source rather than firing on every save is what stops the loop: the job writes the embedding back with `update!`, which commits again, and an unguarded callback would enqueue itself forever.

`DocumentsController#index` runs the search only when `q` is present. A `RubyLLM::Error` from the provider (a 503, a rate limit) is reported to `Rails.error`, so it lands at `/errors`, and the page falls back to the plain list with the `documents.index.search_unavailable` alert instead of a 500. Both the list and the search select only `id` and `title`, the two columns the page renders, so neither loads the embedding blobs; Neighbor keeps an existing `select` and only adds its distance. A view that needs another column must add it there, or it raises `ActiveModel::MissingAttributeError`.

`Document#embedding_source_text` is cut to `Document::EMBEDDING_SOURCE_BYTES` (8,191) bytes, so only the start of a long document is embedded. Every OpenAI embedding model accepts at most 8,191 input tokens, and every token of their byte-level BPE covers at least one byte, so a source of that many bytes fits in any script, emoji included. A character limit would not: one character can be several tokens. Without the cut a long document makes the request fail on context length on every attempt, and the stale embedding stays.

RubyLLM resolves the embedding model against its model registry. In a Rails app the registry store is the gem's own `RubyLLM::ActiveRecord::Model`, over the `ruby_llm_models` table. At boot the gem reads the registry from that table whenever it has at least one row and falls back to its bundled JSON only when the table is empty. A table that holds only some models (one left by an old app, or written by hand) is therefore the whole registry, and `Document.semantic_search` raises `RubyLLM::ModelNotFoundError` for `text-embedding-3-small` when that model is not in it.

`db/seeds.rb` is what keeps the table complete: it writes the bundled JSON into the table through the gem's idempotent `RubyLLM.config.model_registry_store.write`. `bin/rails ruby_llm:load_models` does the same against a running app. `bin/setup` seeds on first creation; an existing checkout runs `bin/rails db:seed`. `test/db/seeds_test.rb` reproduces the one-row table and proves the seed repairs it.

`Document::EMBEDDING_DIMENSIONS` is tied to the embedding model. Changing `OPENAI_EMBEDDING_MODEL` to one with a different output size means a migration, which is why the variable is documented in `.env.example` and nowhere else.
