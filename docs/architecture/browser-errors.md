# Browser errors

`app/javascript/error_reporting.js`, called from `app/javascript/application.js`, listens for `error` and `unhandledrejection` on the window and posts to `JavascriptErrorsController`. The controller wraps the report in a `JavascriptError` (`app/errors/javascript_error.rb`) with the browser stack as its backtrace and hands it to `Rails.error.report` as handled, tagged with a source and the page URL, user agent and user id — so **Solid Errors records browser failures next to server ones at `/errors`**.

Only a report from a signed-in person reaches Solid Errors. An anonymous report goes to `Rails.logger.warn`, where the log viewer shows it. Solid Errors sends one email for every occurrence, and the endpoint takes any message, so an anonymous loop would mail 30 attacker-written messages a minute from the app's own address. A person has to confirm an email address to get a session, so the reports that reach the inbox have an owner.

Both ends are fenced. The client caps reports at `MAX_REPORTS_PER_PAGE = 5` per page load, truncates the message to 1,000 characters and the stack to 4,000, and swallows failures of its own fetch so a broken endpoint cannot start a reporting loop. The server `rate_limit`s at 30 requests per minute, rejects a blank message with `400`, and truncates the message to `MAX_MESSAGE_LENGTH = 1000` characters and the backtrace to `MAX_BACKTRACE_LINES = 20` lines before reporting.

A body over `MAX_BODY_SIZE` (64 KB) is answered `413` by the router, never by the controller. The route carries a constraint, `JavascriptErrorsController.within_body_limit?`, that reads only the `Content-Length`, and a second route for the same path answers with the bare `TOO_LARGE` Rack app. The check cannot live in a `before_action`: Rails instruments every action with the filtered parameters, so the JSON body is already parsed before the first callback runs. The client's own caps keep a real report far under the limit. The stack is split lazily and stops at `MAX_BACKTRACE_LINES`.

The CSRF token is attached when present and never required. `csrf_meta_tags` renders nothing when forgery protection is off, which is the case in test, so requiring the token would silently drop every report there and make the wiring untestable. The server is the enforcement point.

An error thrown from injected script is masked by the browser to a generic message with a null error object, which is why `test/system/javascript_error_reporting_test.rb` dispatches a synthetic `ErrorEvent` instead of throwing one: it exercises the listener, the payload, the request and the recording. Real errors in this app are not masked, because the policy forbids cross-origin scripts in the first place.
